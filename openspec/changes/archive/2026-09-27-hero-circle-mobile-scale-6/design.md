# Design

## Context

Компонент `HeroVisual` в `src/components/Hero.tsx` принимает prop `scale` для управления размером кругового элемента. На мобильных устройствах (breakpoint ниже `lg`) используется отдельная копия компонента с `scale={0.84}` и пропорциональными сдвигами фраз `shiftUpPx={21}`, `shiftDownPx={21}`. См. proposal.md — Why.

## Goals / Non-Goals

**Goals:**
- Увеличить масштаб кругового элемента на мобильных (0.84 → 0.9)
- Сохранить пропорциональные отступы фраз над/под кругом

**Non-Goals:**
- Изменение десктопной версии (scale=1)
- Изменение CSS-анимаций, вращающихся колец или структуры компонента
- Изменение вертикальных резервов (`pt-[28%]`, `pb-[20%]`)

## Decisions

### 1. Значение scale: 0.9
**Решение**: Использовать `0.9` — чистое, читаемое значение.
**Обоснование**: CSS `transform: scale()` принимает произвольные float-значения. 0.9 — круглое число, легко читается в коде и комментариях.
**Альтернативы**: 0.8904 (точный расчёт 0.84 × 1.06) — отклонено по запросу пользователя в пользу 0.9.

### 2. Сдвиги фраз: 23px
**Решение**: `shiftUpPx={23}`, `shiftDownPx={23}` (округление 21 × 0.9/0.84 ≈ 22.5 → 23).
**Обоснование**: Пиксельные значения целочисленные. Округление вверх до 23 компенсирует увеличенный масштаб круга.
**Альтернативы**: 22 — отклонено, т.к. при scale 0.9 фразы будут ближе к кругу, чем нужно.

## Risks / Trade-offs

- **[Риск: фразы ближе к границам экрана]** → Увеличение масштаба остаётся в пределах запаса, заложенного в `wrapperStyle` (`width: min(calc(100% - 2.5rem), calc(100vw - 4.5rem))`). Визуальная проверка на мобильных устройствах подтвердит отсутствие обрезки.
- **[Риск: вертикальный overflow]** → Вертикальные резервы `pt-[28%]` и `pb-[20%]` не меняются. При scale 0.9 круг занимает 90% ширины контейнера. Риск минимален.
