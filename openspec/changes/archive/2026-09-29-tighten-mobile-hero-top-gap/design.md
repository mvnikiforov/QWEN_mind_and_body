# Design

## Context

Текущая геометрия верхней части страницы (см. proposal.md — Why):

| Слой | Класс | Значение |
| --- | --- | --- |
| Секция hero | `pt-32 sm:pt-36` (`Hero.tsx:197`) | 128px / 144px |
| Внутренний контейнер | `px-5 pt-10 sm:px-8` (`Hero.tsx:205`) | +40px |
| Шапка (непроскролленная) | `py-5` + строка 44px (`Header.tsx:29`, кнопка `h-11`) | 84px + `var(--safe-top)` |

Секция начинается с верха документа (шапка `fixed`), поэтому зазор между шапкой и строкой «Онлайн и очно» равен `168px − (84px + safe-top)`: ~84px без safe-area и ~37px на iPhone с вырезом. Отсюда и «дыра» на скриншоте.

Смежные величины, которые нельзя сломать:
- `.site-header { padding-top: var(--safe-top) }` (`index.css:58`) — шапка растёт на безопасную зону.
- `html { scroll-padding-top: calc(96px + var(--safe-top, 0px)) }` (`index.css:19`) — якорная навигация.
- Геометрия кругового визуала (`pt-[28%]`, `pb-[20%]`, `scale=0.9`) — принадлежит capability `hero-visual`, здесь не трогаем.

Спецификация поведения — `specs/hero-layout/spec.md`.

## Goals / Non-Goals

**Goals:**
- Убрать пустую полосу: зазор шапка → «Онлайн и очно» ≈ 8px на ширинах < `lg`.
- Выразить зазор через высоту шапки, а не через независимую константу.
- Сохранить десктопную композицию без изменений.

**Non-Goals:**
- Изменение геометрии кругового визуала, анимаций фраз и колец.
- Изменение состояния `scrolled` у шапки и поведения мобильного меню.
- Рефакторинг системы отступов сайта в целом.

## Decisions

### 1. Единая константа высоты шапки в `:root`
**Решение**: В блоке `:root` (`index.css`, рядом с `--safe-*`) ввести
`--header-h: calc(var(--safe-top) + 84px)` и `--hero-top-pad: calc(var(--header-h) + 8px)`.

**Обоснование**: Требование «Gap derives from header height» выполняется буквально — зазор выражен через ту же величину, из которой складывается высота шапки. Если позже поменяется `py-5` шапки или появится новый safe-area, правится одна строка, а не пара магических чисел в JSX. Кастомные свойства резолвятся на этапе computed-value, поэтому порядок объявлений в `:root` не важен.

**Альтернативы**:
- Захардкодить `pt-[92px]` — отклонено: не переживает ни смену safe-area, ни правку шапки; возвращает рассинхрон.
- Измерять шапку в JS через `ResizeObserver` и выставлять padding — отклонено: лишний рантайм, риск layout shift при загрузке, ради ~80px.
- Считать зазор через `position: sticky`-структуру вместо фиксированной шапки — отклонено: это переработка всей навигации, выходящая за рамки задачи.

### 2. Отступ переносится из контейнера в секцию
**Решение**: `pt-10` у внутреннего контейнера убирается для < `lg` (`pt-0 lg:pt-10`), а секция получает `pt-[var(--hero-top-pad)] lg:pt-36`.

**Обоснование**: Иначе целевой зазор пришлось бы задавать двумя независимыми значениями (секция + контейнер), и любая правка одного из них снова ломает сумму. Свёртка в одно значение делает спецификацию проверяемой по одному месту.

**Альтернативы**: оставить `pt-10` и поставить секции `pt-6` — отклонено: арифметика раскидана по двум узлам.

### 3. `scroll-padding-top` выражается через ту же константу
**Решение**: `html { scroll-padding-top: calc(var(--header-h) + 12px) }` (было `calc(96px + var(--safe-top, 0px))`).

**Обоснование**: 96px было отдельной копией той же величины. Новое значение (84 + safe-top + 12) сохраняет прежний запас в 12px над шапкой, но перестаёт расходиться с ней при правках. Требование «не меньше высоты шапки» выполняется с запасом.

### 4. Контрольная точка `lg` как граница поведения
**Решение**: Новые значения действуют во всём диапазоне < `lg`, десктопные классы задаются через `lg:`.

**Обоснование**: Одноколоночная мобильная/планшетная раскладка hero одинакова на 390px и 900px, поэтому различать их нечем — это подтверждено запросом пользователя. На `lg` включается сетка `lg:grid-cols-12` с визуалом в правой колонке и `items-center`, где прежний воздух часть композиции.

## Risks / Trade-offs

- **[Риск: контент всё же наезжает на шапку при нестандартном safe-area]** → Константа выведена из той же `--safe-top`, что применяется к шапке; расхождение возможно только при правке шапки без правки константы — это ловится визуальной проверкой на iPhone с вырезом (задача в tasks.md).
- **[Риск: `scroll-padding-top` меньше прежнего на широких экранах]** → 84 + safe-top + 12 = 96px + safe-top на десктопе (safe-top = 0) — значение идентично прежнему; на iOS safe-area одинаково в обоих случаях. Регрессии нет.
- **[Компромисс: зазор 8px — плотнее, чем на десктопе]** → Принято осознанно по решению пользователя. Строка «Онлайн и очно» имеет собственный `text-shadow`, поэтому визуально отделима от шапки даже при малом зазоре.
- **[Компромисс: перенос отступа из контейнера в секцию меняет DOM-стили соседних блоков]** → Внутри секции других потребителей верхнего отступа нет; фоновые слои позиционируются относительно самой секции и не зависят от `padding`.
